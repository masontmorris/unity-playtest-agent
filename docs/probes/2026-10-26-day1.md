# Day 1 model probes (26 October 2026)

Every S1 candidate and Muse Spark 1.3 returned valid output on a sample packet. The decision models answer in 0.1–0.8 s. **Muse Spark takes 17–45 s per frontier call at default reasoning effort and 5–6 s at `minimal`.** The output looked equally good at `minimal`, so that is the default.

These are capability, latency and cost checks on one synthetic packet. They are not a quality benchmark; that is the S1 bench (#24). Sample sizes are tiny (n = 2–5 per cell), so treat latencies as indicative. Raw calls are in `runs/probes/` (local only). Scripts: [`scripts/probes/`](../../scripts/probes/).

## S1 candidates

33 calls, all HTTP 200, all valid typed choices. The packet offered 12 choices, with a small history (8 entries) or a large one (110 entries). Image calls added a 1280×720 PNG (a synthetic test pattern).

| Candidate | Resolved model | Small text, median (max) | Large text, median (max) | Small + image, median (max) | Input tokens: small / large / image | Same body, same answer? | Cost |
|---|---|---|---|---|---|---|---|
| mammoth-1 (Baseten) | `decision-models/baseten-mammoth-27b-latest` | 169 ms (170) | 748 ms (756) | 407 ms (464) | 1,407 / 10,895 / 2,418 | Yes, byte-identical | Free trial week; post-trial price not published |
| elephant-1 (Baseten) | `decision-models/baseten-elephant-9b-latest` | 143 ms (258) | 320 ms (331) | 358 ms (446) | 1,407 / 10,895 / 2,418 | Yes, byte-identical | Free trial week; post-trial price not published |
| Liquid d1.1 | `d1.1` | 137 ms (143) | 324 ms (337) | 270 ms (298) | 1,519 / 13,089 / 2,914 | Top choice held; probability ranged 0.25–0.49 | Reported per call: $0.02 per 1M input tokens ($0.0011 for all 11 calls) |

- **Images work on all three.** Baseten takes them as OpenAI-style content parts inside `state.messages`; Liquid takes a top-level `images` array. A 1280×720 frame costs about 1,000 tokens on Baseten and 1,400 on Liquid.
- **Context.** Baseten's limit is 16,384 tokens for both models. Liquid's tokenizer counts the same large packet as 13,089 tokens, 20% more than Baseten's, so "≤ 12k tokens" has to be measured per provider.
- **Billing unit.** Liquid bills per input token and returns `usage.cost`. Earlier per-request vs per-question doubts are resolved for d1.1.
- **A quality flag to test in the bench.** On the small text packet, mammoth-1 chose *Finish the run* with p = 0.55, even though the objective was open and a directive was pending. elephant-1 and d1.1 chose *Interact*. One packet proves nothing, but premature `finish` is a failure the bench must label.

## Muse Spark 1.3 (frontier and preflight)

Six Chat Completions calls with strict JSON-schema output. All returned schema-valid JSON on the first try. Estimated cost: $0.145 at Standard rates ($1.25 / $0.15 cached / $4.25 per 1M tokens).

| Call | Reasoning effort | Latency | Input tokens (cached) | Output tokens (reasoning) | Est. cost |
|---|---|---|---|---|---|
| Small packet | default | 22.7 s | 1,715 (0) | 4,999 (4,641) | $0.023 |
| Same packet again | default | 29.5 s | 1,715 (1,649) | 6,722 (6,356) | $0.029 |
| Large packet | `low` | 9.2 s | 10,795 (0) | 1,863 (1,516) | $0.021 |
| Large packet again | default | 17.4 s | 10,795 (0) | 3,350 (3,062) | $0.028 |
| Small packet + 4 s clip | default | 25.3 s | 2,771 (0) | 3,336 (3,070) | $0.018 |
| Same, again | default | 45.3 s | 2,771 (0) | 5,271 (4,716) | $0.026 |

- **Latency is the risk.** At default effort, one call takes 17–45 s; at `low`, 9 s. In real time at about 1 S1 decision per second, that is 10–45 S1 turns per frontier call. The prototype's DeepSeek frontier took 4–8 s. `while_pending` (S1 keeps playing while help is pending) is therefore load-bearing, not optional. Output cost is about 90% reasoning tokens.
- **Directives come back checkable.** All 6 directives carried an `expected` postcondition (`public.r_item_held == true`) and a deadline. Every cited sequence number existed in the packet. 3 of the 6 proposed a candidate finding on their own.
- **Video is cheap.** A 4 s, 640×360, 10 fps clip added 1,056 input tokens, about $0.0013. Clips, not stills, are affordable for every escalation.
- **Caching is partial.** An identical text-only request hit the cache (1,649 of 1,715 tokens). It did not hit after a `reasoning_effort` change, or on an identical request that included video. With n = 1 each, eviction can't be ruled out.
- **Strict schemas must be closed.** Strict mode rejects any object without `additionalProperties: false` (HTTP 400, not billed). Free-form maps, such as `params: {}`, have to become name/value lists in every schema sent to Muse.

### Follow-up: `reasoning_effort: minimal`

Three more calls on the same packets. All returned schema-valid JSON, and the cost was $0.029.

| Call | Latency | Input tokens (cached) | Output tokens (reasoning) | Est. cost |
|---|---|---|---|---|
| Small packet | 5.3 s | 1,715 (0) | 820 (530) | $0.006 |
| Large packet | 6.2 s | 10,795 (1,393) | 901 (653) | $0.016 |
| Small packet + 4 s clip | 6.3 s | 2,771 (0) | 840 (593) | $0.007 |

- **4× faster and 3× cheaper than the default**, with no visible loss on this packet. All 3 directives had the same checkable postcondition, and each response gave 2–3 hypotheses, each with confirm and refute conditions. The one candidate finding cited a valid sequence number.
- **Latency still sets the cadence.** About 6 s is about 6 S1 turns, so `while_pending` remains necessary.
- The large call got a partial cache hit (1,393 tokens, roughly the system prompt and schema), even though a different effort had been used on the same prefix earlier.

## Preflight (stages 4–6) on real game code

Two calls to Muse Spark 1.3 with six FPSKit gameplay scripts from upstream `8965ad4` (12,900 input tokens). The probe used a regex stand-in for stage-1 discovery, which listed 115 candidate fields. The schema allowed only the discovered field ids, so the model could choose but not invent.

| Effort | Latency | Output tokens | Est. cost | Result |
|---|---|---|---|---|
| `minimal` | 6.4 s | 1,080 | $0.021 | Schema-valid: 12 readers, 1 progress field, 5 invariants, 5 gaps |
| `low` | 10.8 s | 2,139 | $0.025 | Schema-valid: 12 readers, 1 progress field, 6 invariants, 6 gaps |

- **The readers are runtime state, not configuration.** Both runs picked paused, the current attachment, crouch, slide, aim, jump count, dash, yaw/pitch and the interaction hit. 11 of the 12 readers were the same in both runs.
- **The invariants are checkable.** For example, blend values stay in [0, 1], pitch stays inside its clamp, and nothing advances while paused.
- **The gaps are the useful part.** Both runs said position, velocity and grounded state aren't in these scripts. The bridge's generic baseline supplies position and velocity, so the gap list already tells preflight what the baseline must cover. Both runs also noted that FPSKit has no objective, score or health state. That matches the game, and means seeded bugs there must surface through other fields.
- The code excerpts were sent in Standard mode, which Meta does not use for training. Nothing from the game is stored in this repo; the script reads the project from a local path.

### Full project load: 26 scripts

The probe above sent six scripts, 12,900 input tokens. Preflight has to read the whole project, so the same stages were rerun over every non-Editor script in the FPSKit fork at `8965ad4`: **26 scripts, 224 discovered fields, 12 controls (26 bindings), 72,197 characters of code, 26,401 input tokens.** Discovery is the same regex stand-in; the controls come from serialized `InputAction` blocks in the two prefabs.

Seven calls: stages 4–6 at `minimal` and at `low` on `muse-spark-1.3-contributor`, plus stage 4 once on Standard. All 7 returned schema-valid JSON on the first attempt.

| Call | Effort | Latency | Input (cached) | Output (reasoning) | Est. cost |
|---|---|---|---|---|---|
| 4 readers | `minimal` | 10.1 s | 26,401 (0) | 1,043 (507) | $0.0028 |
| 5 actions | `minimal` | 14.4 s | 26,013 (0) | 2,013 (306) | $0.0030 |
| 6 progress | `minimal` | 9.0 s | 29,356 (0) | 875 (576) | $0.0031 |
| 4 readers | `low` | 15.0 s | 26,401 (0) | 1,566 (933) | $0.0030 |
| 5 actions | `low` | 16.5 s | 26,013 (0) | 2,416 (840) | $0.0031 |
| 6 progress | `low` | 18.8 s | 29,322 (0) | 1,485 (1,108) | $0.0032 |
| 4 readers, Standard | `minimal` | 4.7 s | 26,401 (0) | 952 (425) | $0.0370 |

- **The chain is cheap on the contributor tier.** $0.0090 at `minimal` (33.5 s) and $0.0093 at `low` (50.3 s) for all three stages; input is about 90% of the cost. At Standard list prices the same measured tokens project to $0.119 and $0.125. Contributor is 12.5× cheaper on input and 21× on output, but Meta may train on those prompts, so it stays fixtures-only; this project is our own fork.
- **Every stage pays for the whole project.** The three stages send 82k input tokens between them. Nothing was cached, so each is a full-price call.
- **Caching did not fire at this size.** All 7 calls report `cached_tokens: 0`, even though every one repeats the same byte-identical 26k-token discovery-and-source prefix. The smaller Day 1 packet did cache on Standard (1,649 of 1,715). The script sets `prompt_cache_key: "upa-preflight"`; whether the prompt size or the explicit cache key is responsible is not established. Every figure here is a no-cache measurement. If the whole prefix cached, the Standard chain projects to $0.029 instead of $0.119, so one controlled two-call test is worth running before the manifest cache (#28) is built.
- **Latency is acceptable because preflight runs once per project.** 33.5 s or 50.3 s, against a 10-minute run. The 4.7 s Standard call is one stage, not the chain.
- **The choices are stable.** All three runs chose 16 readers, 12 of them the same (13 of 16 between the two contributor runs). Both efforts used all 12 controls, produced 14 actions and 6 skills, and named the same missing controls: pause/resume, UI navigation and reload. The differences are near-duplicates (`crouch` vs `m_Crouch`, `m_Move` vs `m_Movement`), and the 16-reader cap binds every time.
- **Effort and reader choice are confounded.** `low` chose `Paused`, projectile collisions and weapon cooldown in stage 4; `minimal` chose recoil, forces and projectile age. Stage 6 then wrote invariants over different fields. A clean effort comparison must fix stage 4 and vary only stage 6.
- **The `minimal` invariants all hold; `low`'s are richer and one is false.** Checked against source, all 7 `minimal` invariants match the code: clamped blends and pitch, bounded jump count, decaying recoil, shooting requires an attachment, monotonic projectile age. The `low` run's *"When Paused is true it implies movement vector is zero …"* is wrong: `LateUpdate` returns at `if (Paused)` before `UpdateMovement`, so `m_Movement` keeps its last value. Its second clause (jump, dash and crouch do not progress) is right. A checker would fire for any pause while moving. The same run's *"aiming implies dash stays at or decays to zero"* is correct and non-obvious: `dash = CanDash && !aim && …`.
- **"TTL" means three different things here.** `RigidBodyProjectile.m_TTL` and `BasicWeaponAttachment.m_TTL` count up; `PickupDispenser.m_RespawnTTL` counts down. The `minimal` run's `never_decreases` on projectile TTL is true but vacuous: the field is monotonic by construction, so it can only catch a reset. The check that would catch a stuck projectile is a bound against `explodeAfterDelay` (or a reset-on-recycle check), and `explodeAfterDelay` is a discovered field (f212). Neither effort wrote it. Names are not semantics; scoring this belongs to the bench (#24).

## What this changes

1. Frontier calls default to `reasoning_effort: minimal`. Whether `low` or the default are ever worth 2–8× the latency is a bench question for hard cases. One option to evaluate is a proposal, not decided: offer S1 two escalate choices, *quick* (`minimal`) and *deep* (`low`), so the effort level stays S1's decision (law 2) rather than a code threshold.
2. The S1 decision is no longer gated on latency, since all three are fast enough. The bake-off (#25) decides on quality and on what the models cost after the Baseten trial week.
3. Budget figures are in [`docs/budget.md`](../budget.md).
4. Preflight budgeting is now per project: $0.12 for a full 26-script project on Standard with no cache, $0.03 if the prefix caches, and $0.009 measured on the contributor tier. The manifest cache (#28) must not assume hits until one is measured at this size.
