# Day 2 gate — Bridge v0

Date: 2026-10-27. Tree: `f86403f` (the `main` merge of #17 and #18).

Gate criteria from the `Day 2 – Bridge v0` milestone:

1. The fake-game loop passes its invariants.
2. The bridge moves the FPSKit player, supersedes a lease and verifies release.

## 1. Fake-game loop

`uv run pytest tests/test_loop_invariants.py` — **9 passed**.

The scenarios assert on the fake game's input log, not only the loop's own records:

- an invalid decision produces no input (`test_invalid_decision_rejected_no_input`);
- a wait produces no input (`test_wait_sends_no_input`);
- help with `while_pending: continue` runs only the pending choice
  (`test_help_continue_runs_only_pending_choice`);
- help with no pending choice defaults to wait (`test_help_missing_while_pending_defaults_to_wait`);
- a second help while a helper is pending is bounded (`test_second_help_while_helper_pending`);
- a helper resolves exactly once (`test_helper_resolves_exactly_once`);
- a stale act is rejected with no substitute (`test_stale_act_rejected_no_substitute`);
- stop with a held lease releases it (`test_stop_with_held_lease_releases`);
- the full scripted run keeps adherence (`test_full_scripted_run`).

The full Python suite is **294 passed** (`uv run pytest`), so the loop invariants are not passing
in isolation from the contracts, name-blind lint or adherence checks.

## 2. Bridge on FPSKit

Environment: clean `FPSKit-bridge-v0` fork, Unity 6000.5.4f1, Windows, Direct3D11 for PlayMode.
The PlayMode suite ran with a graphics device (`-NoGraphics` is available for machines without
one); EditMode ran with `-nographics`.

- EditMode: **145/145 passed**.
- PlayMode: **9/9 passed**.

The movement test (`ActPlayModeTests.Act_MovesSupersedesHeldInputAndRejectsStaleObservation`)
measured, from its log:

```
forward=2.359m stale_delta=0.000m held=1.018m replace_along=-1.506m stable_delta=0.000m
forward_duration=0.473s held_duration=0.204s replace_duration=0.301s
```

- `forward=2.359m`: the first bounded action moved the controlled body.
- `stale_delta=0.000m`: an act based on a stale observation was rejected and did not move the
  body. No code substituted another choice.
- `held=1.018m`: a second action moved the body while holding the lease.
- `replace_along=-1.506m`: the superseding action moved against the held direction; the previous
  lease was cancelled and released, not continued.
- `stable_delta=0.000m`: after the replacement completed, the body stayed still.
- The cancelled and terminal execution records reported `release_verified: true`.

The stop test (`StopPlayModeTests.Stop_FromMainThreadReleasesAndVerifiesAHeldKey`) held a real key
through the transport, stopped from the main thread as a scene change does, and checked the key
was physically pressed before the stop, the `stopped` result named `key:w` with
`release_verified: true`, the cancelled record was emitted, and the session closed. The clock and
input-release tests also passed, and the capture self-test, host status, frame window and
`frame_ref` round trip passed in the same run.

CI on the two code PRs was green: #79 (stop/clock) and #80 (capture). Movement is used here only
as a diagnostic that the action reached the game; the gate claim is the lease supersession,
release verification and the loop invariants, not progress.
