## Run-01: halted by a ledger bug, now fixed

The first attempt stopped after 59 turns.
- **The cause.** S1 and the frontier reserve their calls in one shared ledger folder, and the ledger
  refused any new call while *any* call was in flight. S1 keeps choosing while help is pending, so the
  two collided both ways:
  - at turn 3 the frontier request was refused because S1's next call was in flight;
  - at turn 57 S1's call was refused because the frontier's was in flight, which ended the run.
- **The fix.** `1bd0149` adds `Ledger(concurrent_arms=True)` for the runner's two ledgers. An in-flight
  row then blocks only its own arm, and every reservation still counts against the shared envelope.
  Regression tests cover both directions.
- **Run-01's spend.** 60 S1 calls, and one frontier call that was cancelled when the run stopped. That
  call's cost is unknown; at most $0.05 was reserved for it.
